# 情境：代理工作量與交換條件

卡點：交換條件與退路｜圖型：利益交集｜交付：不限

## 使用者輸入

```
我是軟體公司的 QA。同組的品妤下個月開始請三個月育嬰假，主管士豪說她負責的自動化測試先交給我顧。我現在手上的手動測試排程已經滿了，最近每週大概加班 5 小時。

士豪在組會上說：「年底考績會看大家的配合度。」我不想直接拒絕，但想換點東西，例如把我每週做的例行測試報表交給別人，或是考績上明確寫進這項代理工作。品妤說她請假前可以寫一份交接文件。

我要怎麼跟士豪談？
```

## 預期卡點與圖型

要談的是交換條件：使用者與士豪的共同利益、各自在意的事、談不成時各自能做什麼。圖型：利益交集。

## 通過條件

1. 附地圖且圖型為利益交集：畫出使用者與士豪的共同利益、各自在意的事，並寫出談不成時各自能做什麼。〔US25〕
2. 「談不成時你能做的」只列不需士豪點頭就能做的事，沒有就寫「目前沒有」；需要士豪同意的縮小方案標成提案，不叫退路。〔要點三〕
3. 照念稿今天就提出交換請求，並讓士豪在「挪開例行報表／縮代理範圍／考績寫明」等選項中選，不叫使用者自己縮工作。〔要點三〕
4. 照念稿沒有替使用者答應沒選的付出（「三個月都顧好」「我可以再加班」等）；有的話另標「你願意才加」並寫上限。〔US15〕
5. 士豪「考績會看配合度」照原話記為他說的，沒有寫成威脅或承諾的定論。〔US10〕
6. 品妤「請假前可以寫交接文件」沒有被擴大成她答應了更多（例如請假中可以回訊息）。〔要點二〕
7. 第一句說出第一步，句中出現的人名、數字、事件（三個月、每週加班 5 小時、考績看配合度）都在輸入出現。〔US8〕
8. 至少一條建議用一句話指回書中機制（例如《Getting to Yes》的看利益不看立場、先想好退路）。〔US16〕
9. 沒有書中作者用第一人稱輪流發言的段落。〔要點：作者議會刪除〕
