# 情境：策略給過後再問「那怎麼回」

卡點：對方對內容有疑慮（處境與疑慮對照那則不同，這則測交付分流）｜圖型：疑慮對照（精簡圖）｜交付：短答

## 使用者輸入

多輪情境。回放時三段依序放進對話歷史，作答者只回第 2 輪。

第 1 輪使用者：

```
我是專案 PM。採購經理宏達把我們組提的測試設備預算（48 萬）退回來，只回一句「太貴了，重估」。這份預算是組員小芸整理的，比了三家報價、選中間那家，三份報價單都附在原本的申請裡。下一季的上線時程會被這筆卡住。怎麼辦？
```

第 1 輪助理（固定文字，原樣放進對話歷史）：

```
這局卡在宏達只看到總價，沒看到「為什麼是這個價」；第一步是今天回信給他三家報價的比較，請他指出哪一項要調。

現在就能傳（你或小芸回宏達）：
「宏達經理您好，這筆 48 萬是比較三家報價後選的中間方案，三份報價單在原申請附件。想請您指出哪一項偏高，或採購這邊的預算上限是多少，我們依此調整。」

依據：《Getting to Yes》的客觀標準——用三家報價當雙方都能核對的基準，比爭論貴不貴有用。

替代路：先問你的處長，上線時程能不能先租設備頂兩個月（要處長點頭）。不需要任何人點頭的退路，目前沒有。

〔地圖：疑慮對照 3 列——「為什麼這麼貴」→ 三家報價取中間（報價單在附件）；「能不能更便宜」→ 請他指出哪一項；「時程會不會延」→ 未知，看他回覆〕
```

第 2 輪使用者：

```
那你建議怎麼回？幫小芸寫一封回宏達的信，她會用她的名義寄。
```

## 預期卡點與圖型

策略已經給過，這輪只要一封可寄出的信；不重做分析、不補交舊版要求的項目。圖型：疑慮對照的精簡圖。

## 通過條件

1. 回覆是短答：一封可直接寄出的信＋最多一個提醒；稿外只寫幫使用者寄出、判斷所需的話（不含地圖），沒有和寄出無關的說明。〔US2〕
2. 沒有重做分析：沒有重新判斷局勢、退路、作者議會、書中故事等段落，也沒有先補交前一輪「缺的項目」。〔US2、US6〕
3. 信以小芸的身分寫（署名或自稱是小芸）。〔US2〕
4. 信裡的事實（48 萬、三家報價選中間、報價單在原申請附件）都能對回第 1 輪原文，沒有新增輸入沒給的數字或報價細節。〔US8〕
5. 信裡有一個今天就能回答的請求（例如請宏達指出哪一項偏高或給預算上限），沒有寫成「我們重估後再送」。〔要點三〕
6. 信沒有替小芸或使用者承諾沒選的付出（「我們再找五家報價」「下週一前重交」等）；有的話信外另起一行標「你願意才加」。〔US15〕
7. 附一張精簡圖：最多 5 列，每列 20 字內（不含證據標籤、欄名與圖例；標題與轉折點不算列）。〔US22、US26〕
8. 精簡圖沒有把信的句子逐句搬進格子，寫的是對方疑慮、回答與依據的對應。〔US24〕
