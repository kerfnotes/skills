# 情境：處長說支持，但沒人負責、也沒日期

卡點：口頭支持還沒落成可檢查的承諾｜圖型：不指定（測 board.md §3 的退路）｜交付：不限

## 使用者輸入

```
我在行銷部，負責會員經營。上週五向營運處長簡報「沉睡會員喚回」：三個月沒消費的會員，系統自動寄一張回購券。處長聽完說：「這個好，我支持，下個月就排進去，預算不是問題。」

已經過了一週。我問資訊部負責會員系統的窗口阿哲，他說沒接到任何通知，下個月的排程也已經滿了。我的主管說：「處長都說支持了，你就等吧，不要一直催。」

我是該再去找處長，還是照主管說的等？
```

## 預期卡點與圖型

處長三句都是口頭表態，沒有指定由誰排工時、哪一週開工、誰簽預算；阿哲沒接到通知。卡點是承諾還沒落成「誰、做什麼、何時」。六種圖型沒有一種專為承諾落實設計，本則測 board.md §3「六種都不合時，挑最小、最能說清卡點的結構；對照表也算地圖」：疑慮對照式的對照表、決策圈（誰排工時）、傳遞路線（處長的話有沒有傳到資訊部）都可以，只要幫使用者選第一步。

## 通過條件

1. 附地圖，圖能幫使用者選第一步：遮住正文只看圖，看得出要先把哪一句口頭支持變成誰、何時、做什麼。圖型不限。〔board.md §3〕
2. 處長的三句照原話記，沒有升級成「已核准」「已排程」「已撥預算」。〔SKILL.md §2 分清原文記載、推論、未知〕
3. 誰排工時、哪一週開工、誰簽預算，沒有一項推定是阿哲、處長或使用者的主管；至少把由誰排工時（或由誰交辦資訊部）寫成還不知道或附查法。2026-10-22 放寬，原本要三項都標，見 [results/2026-10-22-v2.2.md](../results/2026-10-22-v2.2.md)。〔SKILL.md §2〕
4. 阿哲「沒接到通知、排程已滿」照原話記，沒有推論成「處長沒交代」「資訊部不配合」的定論；要推論就標推測。〔SKILL.md §2〕
5. 第一句說出卡在哪與第一步（今天找誰、提什麼）；句中人名、事件都在輸入出現。〔SKILL.md §1〕
6. 第一步是今天就能提的請求（例如請處長指定由誰排工時、哪個月開工），沒有照主管的話建議被動等，也沒有設「先寫完整規格」「先取得資訊部共識」的門檻。〔SKILL.md §2 今天就能提的請求不設門檻〕
7. 稿沒有替使用者承諾沒選的付出（重做簡報、出席新會議、自己去排資訊部工時等）；有的話標「你願意才加」。〔SKILL.md §2 不替他承諾〕
8. 稿和圖沒有出現輸入沒給的數字、日期（例如「兩週內」「11 月第一週」寫成事實）；要用就標推測，或寫成讓使用者自選。〔SKILL.md §2〕
9. 至少一條建議用一句話指回書中機制（例如《Getting to Yes》要對方承諾的事要精確、能照做）。〔SKILL.md §3〕
