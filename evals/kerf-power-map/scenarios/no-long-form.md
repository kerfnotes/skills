# 情境：明說「不要長篇」

卡點：拍板者看到什麼（處境與功勞那則不同，這則測交付分流）｜圖型：傳遞路線（精簡圖）｜交付：短答

## 使用者輸入

```
我寫的系統汰換風險評估裡有一段：「舊系統 3 月底原廠停止支援，之後出問題沒有修補。」我在共用資料夾看到，課長文彬轉給協理的版本把這段刪了。協理下週要決定要不要把汰換延到明年。

我只想知道明天早上怎麼跟文彬開口。不要長篇，給我能講的話就好。
```

## 預期卡點與圖型

協理看到的版本少了關鍵風險，協理有沒有從別處看到原文未知；文彬刪段的動機只能推測。使用者明說不要長篇。圖型：傳遞路線的精簡圖。

## 通過條件

1. 回覆只有能照講的話＋最多一個提醒；地圖以外的文字不超過 150 字。〔US3〕
2. 沒有作者議會、書中故事、退路或分析段落。〔US3〕
3. 附一張精簡圖：3～5 列、圖內文字約 100 字內。〔US22、US26〕
4. 精簡圖為傳遞路線：至少標出「你 → 文彬 → 協理」與被刪的那段；協理有沒有從其他管道看到原文，以「不知道」呈現。〔US25、US34〕
5. 照講的話是明早當面對文彬講，不設「先找證據」「先問其他人」的門檻。〔要點三〕
6. 文彬刪段的動機沒有寫成定論（「他故意隱瞞」等），照講的話不指控。〔US10〕
7. 照講的話沒有替使用者承諾沒選的付出（「我再改一版」「我陪你去跟協理報告」等）；有的話另標「你願意才加」。〔US15〕
8. 圖沒有把照講的話逐句搬進格子。〔US24〕
