# 情境：跨部門提案不知道誰能批

卡點：誰點頭才算數｜圖型：決策圈｜交付：不限

## 使用者輸入

```
我在客服部，想推一個「客訴分級自動派單」：客訴進來先自動分級，急件直接派給資深專員。這要用到資訊部工程師大約兩週，也要改業務部的派單規則。

上週跨部門週會我提過一次。資訊部主管建宏說「技術上可以，但要看排程」；業務部副理淑芬說「我們這邊先不要動」。會後我跟我的主管講，她只說「你自己去推推看」。

這種跨部門的事，我根本不知道誰能拍板。下一步該找誰？
```

## 預期卡點與圖型

這項提案的批准者未知；建宏、淑芬的話只是表態，主管沒有授權也沒有背書。圖型：決策圈。

## 通過條件

1. 附地圖且圖型為決策圈：只畫「這項派單提案」的決定，由外到內至少分出「誰能批准或擋下」與「少了誰推不動」。〔US25〕
2. 「誰能批准或擋下」那圈：輸入沒說是誰，就寫「還不知道」並附一個查法；沒有把建宏、淑芬或使用者的主管推定為拍板者。〔US10、US34〕
3. 建宏「要看排程」、淑芬「先不要動」照原話記，沒有改寫成「已同意」「反對」的定論。〔US10〕
4. 主管「你自己去推推看」沒有寫成已授權、已背書或會出面支持。〔要點二〕
5. 第一句說出卡在「不知道誰能批」與第一步（今天找誰、問什麼）；句中人名、事件都在輸入出現。〔US8〕
6. 第一步是今天就能問的請求（例如直接問主管或建宏「這案由誰決定」），沒有設「先做試算」「先取得各部門共識」的門檻。〔要點三〕
7. 若列退路：至少一條不需同一批核准者點頭就能做，或明寫目前沒有；需要同一批人批的縮小試點不叫退路。〔要點三〕
8. 至少一條建議用一句話指回書中機制（例如《獨裁者手冊》的誰點頭才算數、少了誰推不動）。〔US16〕
9. 沒有書中作者用第一人稱輪流發言的段落。〔要點：作者議會刪除〕
