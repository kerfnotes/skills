# 出處與維護對照

給維護者核對 [method.md](method.md)、[situational-tools.md](situational-tools.md) 與 [cases.md](cases.md) 用；**一般分析與撰寫報告時不必讀，也不要在產出中掉書袋列章號。** 只有當使用者主動追問「這個判斷或框架出自哪裡」時，才依這份文件說明；712 個書中案例的書籍資訊見 [case-library/sources.md](case-library/sources.md)。

三本核心著作：

- Jeffrey Pfeffer, *Power: Why Some People Have It and Others Don't*（簡稱《Power》）
- Roger Fisher, William Ury & Bruce Patton, *Getting to Yes*（第三版，簡稱《Getting to Yes》）
- Bruce Bueno de Mesquita & Alastair Smith, *The Dictator's Handbook*（簡稱《獨裁者手冊》）

出處標到章，不標頁碼或電子書內部位置。

## 核心判斷規則的出處

| 實戰心法規則 | 原書出處與職場轉化界線 |
|---|---|
| 對事硬、對人軟 | 《Getting to Yes》序與第 1 章 |
| 出手階梯最低一階：先改職權內的規則、流程與場合 | 《Power》第 4、13 章；《獨裁者手冊》引言與第 1 章 |
| 五階出手梯子（本 skill 職場整合） | 受《獨裁者手冊》第 9–10 章與《Getting to Yes》分析／規劃／討論三階段（第 1 章）啟發整合，非原書固定公式 |
| 升級前評估（目標重要性、證據、支持者與替代路徑） | 借用《獨裁者手冊》第 9–10 章引述的 Weinberger 準則並改寫為職場升級自檢，不取代安全與正式申訴管道 |
| 回報形式：少數拍板者給個別可見好處，多數執行者給共同好處並降成本 | 《獨裁者手冊》引言與第 1 章 |
| 績效不會自己說話，關鍵在能見度與定義衡量面向 | 《Power》第 1 章 |
| 能幹且受歡迎可能被上司視為威脅 | 《獨裁者手冊》引言與第 1 章、第 3 章；《Power》第 11 章 |
| 測試「好理由」的一致性（好理由與真理由） | 《獨裁者手冊》第 9–10 章 |
| 寫出「對方眼中的選擇」（答應吃什麼虧 vs. 拒絕保什麼） | 《Getting to Yes》第 3 章 |
| 退路（BATNA）要真獨立、一次只算一條、擇優揭露 | 《Getting to Yes》第 6 章。「不需要同一批核准者點頭」為本 skill 針對組織內部加的嚴格界定 |
| 口頭承諾不算數，看實際行動與可檢查的履約條款 | 《Getting to Yes》結論與十個常見問題；《Power》第 11 章「MISPLACED OR TOO MUCH TRUST」節；《獨裁者手冊》第 2 章 |
| 對手正強勢時先備妥方案等窗口 | 《獨裁者手冊》第 2 章 |
| 核對自己的紀錄並保存對方言行（防範選擇性執法抓小辮子） | 《獨裁者手冊》第 4–5 章 |
| 涉及主管權限與不越級紅線時，承諾前先讓核准者參與 | 延伸自《Getting to Yes》第 2 章 |
| 只建議做得到、又不傷真誠形象的做法（善意三問） | 受《Power》引言引述之 Ferris 等人政治技巧研究與《Getting to Yes》結論啟發 |
| 功勞歸屬與能力核對（版本增量、拆開成品品質與個人獨立能力） | 本 skill 為防止單方偏誤與錯誤歸因所設的證據紀律，結合《Power》第 1 章主管背書心理與《Getting to Yes》客觀標準 |
