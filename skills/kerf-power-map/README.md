## 為什麼

職場卡住時，你需要的通常不是一篇分析，而是一封今天就能寄的信、一段當面能講的開場。Power Map 用《Power》《Getting to Yes》《獨裁者手冊》的書中機制與案例，把你這一局變成能直接用的建議與開口說法，每輪附一張視覺化的權力地圖。正文說做什麼，地圖說為什麼站得住、下一步該選哪個。

## 三本書，各管一件事

| 書 | 它回答的問題 |
| :--- | :--- |
| 《Power》 | 權力從哪來：資源、可見度、誰離不開誰 |
| 《Getting to Yes》 | 怎麼談：看利益不看立場、用對方承認的客觀標準、準備好退路 |
| 《獨裁者手冊》 | 誰的支持讓拍板者坐穩；只轉成正當的職場做法 |

三本書拆成三段九步的心法（看局、定打法、落地，見 [method.md](references/method.md)）。隨附 99 筆有完整情節的書中故事，另有 712 筆一句摘要的案例索引；故事只在能分出兩個做法時出場，寫明和本案差在哪、因此選哪個做法。

## 先看用途，再決定給多少

| 你要拿去做什麼 | 它交什麼 |
| :--- | :--- |
| 回信、代寫、解釋疑慮、寫書面說明 | **短答**：能直接寄出的稿、最多一個提醒、精簡圖；稿外只寫寄出和判斷需要的話 |
| 明說不要長篇，或給了字數上限 | **極短**：只給照講的話和最多一個提醒 |
| 第一步取決於一件你很可能知道的事 | **判讀輪**：最多問三題，先給今天就能送的話，附分支圖 |
| 要整體打法，或比較幾條路 | **完整策略**：判斷與第一步、能用的稿、依據與退路 |
| 回報進展、追問、收尾 | **續問**：只更新受影響的判斷、稿和圖裡的格子 |

篇幅看用途，不看你寫了多長的背景。稿照你下一步實際用的管道給：在信件或訊息串裡回就給全文，當面談就給開場。

## 軍師的規矩

- **第一句就講卡在哪、今天先做什麼。** 你帶草稿來時，這句點名稿內已有的和缺的那句；它自己上一輪的回覆不算你的草稿。
- **事實對得回你的原話。** 推測、未知分開標；一個人說的不放大成整個部門，「再看看」不算同意，原文沒有的數字或時長不補。
- **不知道就問你。** 只影響稿中一句時，先寫最可能的版本，旁邊問「X 對嗎？不對的話，這句換成『Y』」。稿裡不留任何待填空格。
- **對準對方真正擔心的事。** 對方只要安心時，一句理由勝過推導和數值表。
- **付出由你自己選。** 要你多花時間力氣、讓出條件、替人作保的話，就算寫成給對方挑的選項，也只放在「你願意才加」，並寫上限或代價。
- **今天能問就今天問。** 由誰決定、期限這類問題，不設「先整理好、先證明」的門檻。
- **退路要真的獨立。** 不需要同一批人點頭也做得到的才算退路；沒有就說「目前沒有」。

## 六種地圖

先判斷卡在哪，再挑一種圖型。每張圖固定兩樣：一句「卡在哪」的判斷標題，和一格標亮的轉折點寫第一步找誰、提什麼；手機上不用捲動就看得到。

| 卡點 | 圖型 | 回答的問題 |
| :--- | :--- | :--- |
| 對方對說明內容有疑慮 | 疑慮對照 | 對方心裡的問題、你的回答、靠什麼撐住 |
| 誰點頭才算數 | 決策圈 | 誰能批准或擋下，少了誰推不動 |
| 拍板者看到什麼 | 傳遞路線 | 資訊經過誰、在哪一段被過濾 |
| 關鍵事實未知 | 分支 | 是或否，第一步各改成什麼 |
| 各方立場 | 立場四象限 | 影響力 × 支持度，先找誰 |
| 交換條件與退路 | 利益交集 | 雙方都要什麼、談不成時各自能做什麼 |

規格與範例見 [board.md](references/board.md) 與 [examples](references/examples/index.md)。

## 怎麼確認它有變好

每次改版都用情境題組重跑：作答者只讀 skill 的隔離複本，看不到評分條件；評分交給沒參與改版的另一個模型逐條判；地圖另跑手機寬度與深淺色檢查。沒過就照實寫，不改條件湊分數。題組與結果在 repo 根目錄的 [evals/kerf-power-map](https://github.com/kerfnotes/skills/tree/main/evals/kerf-power-map)。

## 交給 agent 安裝

把這段交給 Codex 或 Claude Code：

```text
請把 https://github.com/kerfnotes/skills 裡的 Power Map（skills/kerf-power-map）安裝到目前專案。
先讀 skills/kerf-power-map/docs/install.md，依目前使用的 agent 選擇安裝路徑，
完成檢查後回報安裝路徑、來源 commit 及驗證結果。
```

Codex 的專案路徑是 `.agents/skills/kerf-power-map/`；Claude Code 是 `.claude/skills/kerf-power-map/`。不需要額外工具或模型。也可以用 [`skills`](https://www.npmjs.com/package/skills) CLI 從整個 repo 挑：

```sh
npx skills add kerfnotes/skills --list
```

## 開始使用

安裝完成後直接描述你的局面，例如：

```text
主管要我把專案延期的原因寫給客戶，這是我的草稿，幫我改成能寄出的版本
跨部門會議上我的提案被擋，下週要再提一次，我該先找誰？
```

Codex 也可用 `$kerf-power-map`，Claude Code 可用 `/kerf-power-map`。

## 已知限制

- 案例是依書中章節自行改寫的摘要，不是原文；書中沒寫的行動、結果與條件一律標為未知。要核對細節，請回到原書對應章節。
- 分析只根據你提供的資訊，看不到對方的想法與組織內情；建議裡的推測會標明，需要你實地查證。
- 推理強度會影響品質與速度：較低強度比較常替你多答應一件事，或把推測講成事實。重要的局面建議用最高強度，照念前自己再看一眼。2026-10-21 改版後的速度與錯誤率尚未重新量測。
- 這是策略思考的輔助，不是法律、人資或心理諮商意見。涉及勞動權益、申訴或健康時，請找專業人士。
