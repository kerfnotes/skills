# 地圖指引

每次畫圖、更新圖前讀。上位規則在 [SKILL.md](../SKILL.md) 第 4 節；樣式從 [board-template.html](board-template.html) 的零件挑；範例照 [examples/index.md](examples/index.md) 只讀最接近的一例。

## 1. 每輪一張，大小跟交付走

- 每輪回覆都附一張圖，短答也不例外。續作時圖還適用就沿用，只改受影響的格子，正文用一行說改了哪幾格；轉折點或圖型變了才重畫。只道謝的收尾不重貼圖，前一張仍適用。
- 短答與判讀輪用精簡圖：最多 5 列，每列 20 字內（不含證據標籤與欄名）。一列是一格對照、一段傳遞或一個節點，連同人名與線上標籤；標題、轉折點與圖例不算列，字數不算空白與標點。完整策略用一到兩塊完整面板。
- 正文寫說什麼、做什麼；圖寫為什麼站得住、該選哪一步。照念稿和正文講過的理由不搬進圖；圖裡某句和正文同一句，刪掉一邊。

## 2. 固定的只有兩樣

1. **判斷標題**：一句話說卡在哪，人名、數字對得回原文；確定程度跟著證據走，還不知道就寫還不知道。不讀證據也寫得出來的標題只是重述計畫，重寫。
2. **轉折點**：緊接標題、加 `data-focal`，寫第一步：對誰、提什麼，和正文推薦一致。手機上不捲動就看得到。

其他區塊沒有固定順序，照圖型需要放；沒用到的線型或標籤就不放圖例。

## 3. 選圖：先判卡點，再挑圖型

動手前先寫一句「這張圖幫使用者選哪一步」，例如「會前先找志遠還是佳蓉」。寫不出來就是圖型挑錯了，換一種。

| 卡點 | 圖型 | 回答的問題 | 零件 | 範例 |
|---|---|---|---|---|
| 對方對說明內容有疑慮 | 疑慮對照 | 對方心裡的問題 → 你的回答 → 有沒有依據 | `.qa-r` | [包裝改版](examples/concern-nutrition-label.md) |
| 誰點頭才算數 | 決策圈 | 這項決定誰能批准或擋下、少了誰推不動 | `.ring` | [首件表改拍照](examples/circle-first-article-photo.md) |
| 拍板者看到什麼 | 傳遞路線 | 資訊經過誰、在哪一段被過濾或斷掉 | `.route`、`.edge` | [壓測風險被刪](examples/relay-go-live-risk.md) |
| 關鍵事實未知 | 分支 | 這個事實是或否，第一步各改成什麼 | SVG `.bx`、`.ln` | [借調單結束日](examples/branch-secondment-end-date.md) |
| 各方立場 | 立場四象限 | 影響力 × 支持度，誰該先找 | SVG `.ax`、`.dot` | [進料抽檢提案](examples/quadrant-inspection-proposal.md) |
| 交換條件與退路 | 利益交集 | 雙方都要什麼、各自在意什麼、談不成時各自能做什麼 | SVG `.bx` 兩圓 | [設計支援](examples/venn-design-support.md) |

- 判讀輪預設用分支。一張圖只用一種圖型；兩種都想用，挑承載判斷的那種，另一種縮成圖下一行。
- 六種都不合時，挑最小、最能說清卡點的結構；對照表也算地圖。
- 疑慮對照：一列一個對方心裡的問題；草稿已答到的標稿內已有，缺的那列加 `data-focal`。每列的回答寫出靠什麼撐住（外部規定、文件、自己的決定），不重抄正文的清點句。
- 決策圈：只畫第一步要處理的那一項決定，圈照「少了誰不行」分，不照職級；只被告知的人不進圈。批准或擋下那圈一定畫，不知道是誰就寫還不知道和查法。拍板者靠誰坐穩（核心致勝聯盟），只在他自己的位置會影響這項決定時在圈外寫一行。
- 傳遞路線：一列一段傳遞，至少一列已發生、一列建議你做；被過濾的原話寫在那一段。不知道拍板者有沒有收到，畫成點線問句，不畫成斷線。
- 分支：一個待問的事實，每種答案一支；每一支的第一步都要今天就能做，不能是等別人回覆。
- 立場四象限：每人一點，名字在點旁、不跨中線。只開條件、沒表態的人放格外虛線框（`.off`），標〔立場未知〕。
- 利益交集：兩圈各寫自己在意的，重疊處寫雙方都要的；圈下寫談不成時各自能做的。

## 4. 刪到不能再刪

- 每個節點是一個獨立的意思；總是一起出現的兩個節點合成一個。
- 連線要帶資訊；從位置就看得出的關係不畫線。
- 強調最多 2 處，轉折點佔一處，另一處留給缺口或關鍵人；其他都用中性色，重點才顯得出來。
- 上限：精簡圖 5 列或 5 個節點；完整面板 9 個節點、12 條連線。超過就拆成兩塊，或回頭刪。
- 畫完做刪減測試：能不能刪掉一個節點、合併兩個節點、刪掉一條線或一個標籤？還能刪就刪。
- 換案測試：遮住正文只看圖，要看得出卡在哪、第一步是什麼；人名換成別的案子還能照用，就重畫。

## 5. 反模式

- 信件時間軸：一條箭頭一封信，只重述經過，看不出在哪一段出問題。
- 組織圖套同心框：照職級排圈，看不出誰握否決、誰決定能不能落地。
- 正文搬進表格：和正文重複，選不出下一步。
- 人物關係圖：畫你被兩邊拉，換成任何夾在中間的人都能套。
- 所有節點一樣大，抹掉誰份量大；每個重要的都上強調色，等於沒有強調。
- 圖例浮在圖中間壓到節點：放圖下一行，只列用到的。
- 箭頭標籤壓在線上、斜線連線：連線走水平、垂直折線，標籤離開線。

## 6. 證據標籤

- 用 `.tag` 寫成文字，不只靠顏色；SVG 裡寫〔推測〕這類括號字。五種：
  - **已核對**：實際讀過文件，內容支持這句。
  - **稿內已有**：使用者給的草稿已經寫到。
  - **推測**：你的判斷。對方動機與立場一律是推測。
  - **未知**：沒人知道，要查；會改變下一步的才附查法。
  - **待問你**：只有使用者知道，這輪就問。
- 使用者自己說的事不標。
- 圖和正文同一個確定程度：正文說未知的，圖題和轉折點不寫成定論。表態照原話記，不升級成同意；立場未知不猜成中立。
- 線型分清現況與計畫：實線＝已發生，虛線＝建議你做，點線＝不知道有沒有這條路。寄信、收副本不等於能影響對方。面積、粗細、顏色只表達有證據的差異，不捏造功勞比例。
- 退路只寫不用對方點頭就能做的事；要同一批人批的縮小方案是提案，不是退路。沒有就寫「目前沒有」。

## 7. 外觀、手機與無障礙

- 沿用介面主題變數：`--foreground`、`--muted-foreground`、`--border`、`--accent`、`--success`、`--warning`、`--destructive`、`--radius`、`--font-sans`；不覆寫 `:root`，html、body 和最外層容器不設背景。
- 不載入外部字型、CDN 或圖片，只用內嵌 CSS 和 SVG；引用信件文字要跳脫。避開米白／奶油底、標題斜體、等寬字標籤、膠囊按鈕、01／02 裝飾編號。
- 375 寬不截斷、不溢出、不左右捲動。HTML 型的圖（疑慮對照、決策圈、傳遞路線）靠換行；SVG 型（分支、四象限、交集）用 360 寬直式畫布、寬度 100%。
- 每個 `<svg>` 加 `role="img"`，`aria-labelledby` 指向它自己的 `<title>`（第一個子元素）和 `<desc>`（一句話說圖的內容與結論），id 每張圖不同。關鍵資訊不只靠顏色或滑鼠懸停。

## 8. 驗收與交付

1. 用 `html_preview` 以 `width=375` 預覽，實際看截圖：長名字和標籤有沒有截斷，字、線、箭頭有沒有重疊。
2. 手邊有 repo 的 `evals/kerf-power-map/map-check.js` 時，預覽版在 `</body>` 前貼上它，console 要 7/7 PASS；沒有就照第 4、6、7 節逐項看截圖。
3. 交付版不含 script，用 `html_render` 放進回覆。使用者要可下載的檔案才另存；預覽暫存檔不算交付。
4. 只有 Markdown 的環境，同一圖型改成表格（疑慮對照「對方的問題｜你的回答｜依據」、決策圈「圈｜人與依據」、傳遞路線「誰 → 做了什麼 → 誰｜線型」，其他圖型列「條件或人｜第一步或在意什麼」），並說一句沒做視覺驗收。
5. 預覽受阻（工具不在、權限拒絕）就交 Markdown 版，寫明哪些視覺項目沒驗到；不換工具繞過。
